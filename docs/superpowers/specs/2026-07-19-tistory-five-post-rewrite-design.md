# 티스토리 5개 게시글 전면 재작성 설계

## 목표

티스토리의 19번, 20번, 21번, 22번, 29번 글을 강의 필기나 단편적인 설정 메모가 아닌, 검색 방문자가 문제를 독립적으로 해결할 수 있는 기술 문서로 전면 재작성한다. 다섯 글은 모두 공개 상태를 유지하는 것을 기본으로 하되, 저장 전에 독창성·정확성·검색 의도 충족 여부를 통과해야 한다.

## 대상 게시글

| 번호 | 기존 주제 | 새 글의 역할 |
| --- | --- | --- |
| 19 | React 소개 강의 필기 | React와 컴포넌트, props, state를 작은 실행 예제로 설명하는 입문 글 |
| 20 | Create React App 개발환경 구축 | Vite 기반 React 프로젝트 생성과 개발환경 점검 글 |
| 21 | 샘플 앱 실행 | 개발 서버 실행·종료와 대표적인 실행 오류 해결 글 |
| 22 | JS·CSS·build 필기 | React 프로젝트 구조, CSS 적용, production build와 preview 글 |
| 29 | `strictNullChecks: false` 설정 메모 | React/TypeScript에서 null을 안전하게 모델링하고 처리하는 글 |

## 선택한 접근법

다섯 글을 서로 연결된 React/TypeScript 미니 시리즈로 만들되, 각 글은 다른 글을 읽지 않아도 이해되고 실행되어야 한다. 오래된 강의 순서를 요약하는 방식은 폐기하고, 현재 공식 문서와 직접 작성한 예제를 기준으로 내용을 새로 구성한다.

통합 후 일부 글을 비공개로 돌리는 방식은 이번 범위에서 사용하지 않는다. 다섯 주제가 각각 별도의 검색 의도를 가질 수 있으므로, 중복 문단을 만들지 않고 각 글의 문제와 결과를 명확히 분리한다.

## 공통 콘텐츠 구조

모든 글은 다음 순서를 따른다.

1. 독자가 겪는 문제나 달성하려는 결과를 첫 문단에서 제시한다.
2. 적용 환경과 전제 조건을 짧게 명시한다.
3. 복사하여 실행할 수 있는 최소 예제를 제공한다.
4. 코드가 동작하는 이유를 작성자의 문장으로 설명한다.
5. 흔한 실패 사례와 확인 방법을 제공한다.
6. 권장 방법과 피해야 할 방법을 구분한다.
7. 관련된 나머지 글과 공식 문서를 연결한다.
8. 핵심 내용을 세 문장 이내로 정리한다.

강의명, 강의 회차, 타 블로그 문장을 중심으로 글을 구성하지 않는다. 외부 자료를 참고할 때에는 공식 문서를 우선하고 링크를 남기되, 본문 설명과 예제는 새로 작성한다.

## 글별 설계

### 19번: React와 컴포넌트 이해하기

- 제목 방향: `[React] 컴포넌트·props·state를 하나의 예제로 이해하기`
- 검색 의도: React가 필요한 이유와 컴포넌트의 역할을 실제 코드로 이해하려는 독자
- 실행 결과: 이름을 props로 받고 버튼을 누르면 숫자가 증가하는 작은 컴포넌트
- 핵심 설명: UI를 컴포넌트로 나누는 기준, props와 state의 차이, 재사용이 실제로 발생하는 지점
- 제외 내용: React의 역사 나열, 라이브러리의 사전적 정의, 외부 실습 사이트 링크만 나열하는 구성

### 20번: Vite로 React 개발환경 만들기

- 제목 방향: `[React] Vite로 개발환경 만들기 — 설치·실행·폴더 확인`
- 검색 의도: 새 React 프로젝트를 현재 방식으로 생성하고 실행하려는 독자
- 실행 결과: Vite 프로젝트 생성, 의존성 설치, 개발 서버 실행, 초기 화면 확인
- 핵심 설명: Node.js와 npm의 역할, `npm create vite@latest`, 프로젝트 폴더에서 실행해야 하는 이유
- 오류 처리: Node/npm 명령을 찾지 못하는 경우, 잘못된 작업 폴더, 이미 사용 중인 포트
- 제외 내용: 전역 `create-react-app` 설치와 오래된 Create React App 화면 중심 설명

### 21번: React 개발 서버 실행과 오류 해결

- 제목 방향: `[React] 개발 서버 실행·종료와 자주 발생하는 npm 오류 해결`
- 검색 의도: 받은 프로젝트나 기존 프로젝트를 실행하다 막힌 독자
- 실행 결과: `npm install`, `npm run dev`, `Ctrl+C`를 이용한 정상 실행과 종료
- 핵심 설명: `package.json`의 scripts가 명령을 결정한다는 점, 의존성 설치와 서버 실행의 차이
- 오류 처리: `Missing script`, 모듈 누락, 포트 충돌, 잘못된 디렉터리, 손상된 설치 상태
- 20번과의 경계: 20번은 새 프로젝트 생성, 21번은 이미 존재하는 프로젝트의 실행과 진단에 집중

### 22번: 프로젝트 구조·CSS·production build

- 제목 방향: `[React] 프로젝트 구조와 CSS 적용, production build 확인하기`
- 검색 의도: 생성한 React 프로젝트의 파일 역할을 이해하고 배포용 결과물을 만들려는 독자
- 실행 결과: 컴포넌트와 CSS 수정, `npm run build`, `npm run preview`로 결과 확인
- 핵심 설명: `index.html`, `src/main.*`, `App.*`, assets의 연결 관계와 개발 서버·빌드 결과의 차이
- 오류 처리: CSS import 경로, 대소문자 오류, 빌드 실패, 빌드 결과물을 파일로 직접 열었을 때의 문제
- 제외 내용: 특정 과거 템플릿의 줄 번호와 오래된 화면 캡처에 의존하는 설명

### 29번: TypeScript의 null 안전 처리

- 제목 방향: `[TypeScript/React] null 타입 오류 해결 — strictNullChecks를 끄기 전에`
- 검색 의도: React 상태나 API 응답에서 `null` 타입 오류를 해결하려는 독자
- 실행 결과: `useState<User | null>`과 타입 좁히기, 옵셔널 체이닝, 기본값 처리
- 핵심 설명: 오류 원인, 유니온 타입, 조건 검사, `strictNullChecks: false`가 프로젝트 전체에 미치는 영향
- 주의 사항: non-null assertion(`!`)은 런타임 검사를 추가하지 않는다는 점
- 결론: 새 코드에서는 null 가능성을 타입에 명시하고 검사하는 방식을 권장

## 내부 연결 구조

- 19번은 실습 환경이 필요한 독자에게 20번을 연결한다.
- 20번은 생성한 프로젝트의 실행 문제를 다루는 21번과 구조·빌드를 다루는 22번을 연결한다.
- 21번과 22번은 TypeScript 템플릿에서 null 오류를 만난 경우 29번을 연결한다.
- 29번은 React 상태 예제를 이해하기 위한 기초 글로 19번을 연결한다.

링크는 본문 흐름에 필요한 위치에만 넣고, 모든 글에 동일한 링크 목록을 반복하지 않는다.

## 편집 흐름

각 글은 한 편씩 다음 절차를 완료한 후 다음 글로 넘어간다.

1. 현재 제목·본문·카테고리·태그를 기록한다.
2. 공식 문서로 명령어와 동작을 확인한다.
3. 제목과 본문을 전면 교체하되 기존 URL은 유지한다.
4. 카테고리를 React 또는 TypeScript로 정리하고 태그 수를 필요한 범위로 제한한다.
5. 미리보기에서 제목 계층, 코드 블록, 링크, 모바일 가독성을 검사한다.
6. 공개 상태로 저장한다.
7. 공개 페이지를 다시 열어 본문 누락, 깨진 코드, 잘못된 링크를 확인한다.

29번을 먼저 완료해 형식과 편집 안정성을 검증한 다음 19번, 20번, 21번, 22번 순서로 진행한다.

## 오류 및 안전 처리

- 저장 전에는 기존 본문을 별도로 기록하여 복구 가능한 상태를 유지한다.
- 기술 내용이 공식 문서와 충돌하면 공식 문서를 기준으로 수정한다.
- 편집기에서 본문이나 코드 블록이 깨지면 저장하지 않고 해당 글의 편집을 중단한다.
- 공개 저장 후 내용이 누락되면 다음 글로 넘어가지 않고 즉시 해당 글을 복구한다.
- 다른 공개 글이나 사용자의 로컬 프로젝트 파일은 이번 작업 범위에서 변경하지 않는다.

## 품질 검증 기준

각 글은 아래 조건을 모두 만족해야 공개 저장한다.

- 제목이 하나의 구체적인 검색 의도를 표현한다.
- 본문만 읽고 최소 예제를 실행할 수 있다.
- 코드 앞뒤에 목적과 결과 설명이 있다.
- 외부 글의 문장을 바꿔 쓰는 방식이 아니라 새로 작성한 설명이다.
- 글별 핵심 내용이 다른 네 글과 중복되지 않는다.
- 현재 공식 문서에서 확인한 명령과 권장 방식을 사용한다.
- 실패 사례 또는 주의점이 최소 하나 포함된다.
- 미리보기와 공개 페이지에서 코드·링크·문단 구조가 정상이다.

## 완료 조건

- 19번, 20번, 21번, 22번, 29번이 새로운 제목과 본문으로 공개되어 있다.
- 다섯 글 모두 서로 다른 검색 의도와 독립적인 실행 예제를 가진다.
- 강의 필기 형태와 오래된 Create React App 중심 설명이 남아 있지 않다.
- 다섯 글의 내부 링크와 공식 문서 링크가 정상 작동한다.
- 저장 전후 검수 결과에서 본문 누락이나 편집기 손상이 발견되지 않는다.

이 작업은 공개 콘텐츠의 품질을 높여 애드센스 재검토 준비도를 개선하는 것이 목적이다. 애드센스의 최종 승인 여부를 기술적으로 확정하는 작업은 범위에 포함하지 않는다.
